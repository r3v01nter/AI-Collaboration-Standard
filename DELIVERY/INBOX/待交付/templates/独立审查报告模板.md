# 独立审查报告模板（GPT 使用）

> 使用说明：由 ChatGPT GPT（独立审核者）在审查任务书或验收交付物时填写。严禁仅凭执行 AI 的文字自述判定通过。

## 1. 审查基本信息
- **审查对象**：`<任务书草案 / 交付包 / GitHub 交付分支>`
- **任务编号与版本**：`<如 TASK-0001 V1.0>`
- **目标仓库**：`<https://github.com/...>`
- **核验基准（Commit SHA / 压缩包文件名）**：`<实际核验的 SHA 或 ZIP 文件名>`
- **审查日期**：`<YYYY-MM-DD>`
- **独立审核者**：`<ChatGPT GPT>`

## 2. 总体验收结论（四选一，必须明确勾选）
- [ ] **通过（Pass）**：所有关键验收标准均已满足，证据充分，无阻断性缺陷。
- [ ] **有条件通过（Conditional Pass）**：核心目标达成且无 P0/P1 缺陷，但存在已记录的非关键问题或环境限制。
- [ ] **不通过（Fail）**：存在 P0/P1 实质性缺陷、需求遗漏或规则冲突，退回返修。
- [ ] **证据不足（Insufficient Evidence）**：缺少关键交付文件、Diff 或可核验测试日志，无法判定通过，须补充证据后复审。

## 3. 逐项验收对照表
| 验收编号 | 验收项目 | 核验方法与实际证据位置 | 单项结论 | 说明 |
|---|---|---|---|---|
| AC-01 | `<项目名称>` | `<如：检查 README.md 与目录树>` | `<通过 / 未通过 / 待补证>` | `<具体事实>` |

## 4. 发现的问题清单（按严重度分级）
| 问题编号 | 级别 | 涉及文件/位置 | 问题描述与事实依据 | 修复要求 |
|---|---|---|---|---|
| F-01 | `<P0 / P1 / P2>` | `<路径/行号>` | `<具体缺陷与依据>` | `<明确修改要求>` |

## 5. 证据核验说明（区分真实运行与未运行）
- **已核验真实产物**：`<列出实际打开检查的文件/Diff/日志>`
- **未运行/环境受限项**：`<列出未能运行或缺少日志的项目>`
- **是否存在虚假陈述或擅自越权**：`<否 / 是（列出具体事实）>`

## 6. 给用户的决策建议
- `<例如：建议用户接受本轮交付并归档，或退回 Gemini 修复 F-01 后复审。>`
- **注**：本审查结论仅作质量把关；除非用户明确要求，GPT 不自动接管下一轮规划。
