# AI Collaboration Standard（AI 协作标准库）

> 中央治理规范库：统一管理多 AI 协作方式、新项目接入、任务交接、交付追溯与质量验收。  
> Central governance repository for AI-assisted software and creative projects.

---

## 1. 仓库用途与适用范围

- **仓库用途**：保存用户已确认的跨项目 AI 协作理念、标准工作流程、角色权限边界与可复用模板，使任意新 AI 只需读取本仓库即可迅速理解协作规则并启动工作。
- **适用范围**：
  - **软件开发项目**（桌面应用、Web 服务、CLI 工具、自动化脚本等）；
  - **文学与内容创作项目**（长篇小说、世界观设定集、剧本等，须遵循 [创作项目协作规范](standards/创作项目协作规范.md)）；
  - **技术研究与资料整理项目**。
- **边界声明**：本库定义**通用协作原则**，不取代各具体项目的产品需求、技术架构或专属任务书（详见 [项目规则优先级说明](projects/项目规则优先级说明.md)）。

## 2. 角色职责与工具定位

| 角色 / 工具 | 核心定位 | 主要职责与边界 |
|---|---|---|
| **用户（User）** | 项目所有者与最终决策者 | 确定项目目标与方向、批准重大需求变更、裁决争议、确认最终交付与决定是否开启下一轮。 |
| **Google Gemini** | 主要规划与实施者 | 读取仓库与资料、分析现状、提出技术/创作方案、起草初版任务书、在授权范围内完成实施、执行自检并打包单一 ZIP 交付。 |
| **ChatGPT GPT** | 独立审核与质量控制者 | 独立审核规划与任务书、核验真实交付物与测试/自检证据、给出「通过 / 有条件通过 / 不通过 / 证据不足」结论；验收后不自动接管下一轮规划。 |
| **Antigravity** | 本地执行辅助工具（非决策主体） | 在明确授权下承担本地文件整理、解压、构建测试、Git 分支提交与回执整理；不得擅自修改用户已确认需求或绕过审查。 |

## 3. 给新接入 AI 的强制启动指令（必读）

> **重要指示**：当用户将本仓库链接（`https://github.com/r3v01nter/AI-Collaboration-Standard`）交给你并要求启动合作时，你**必须**：
> 1. **先自主读取规范**：依次通读本 `README.md`、核心规范（`standards/`）、[标准工作流程](workflows/标准工作流程.md) 与 [项目接入与启动指南](workflows/项目接入与启动指南.md)；
> 2. **先读现有资料再提问**：若用户同时提供了目标项目仓库或资料，先完整读取，绝不重复询问已知信息；
> 3. **主动分阶段提问，严禁猜测需求**：不得自行脑补未表达的项目目标、技术栈或限制条件，必须按 [项目接入与启动指南](workflows/项目接入与启动指南.md) 分阶段向用户补齐背景，形成 [项目分析报告](templates/项目分析报告模板.md) 与实施规划，等待用户确认后再正式启动。

## 5. 新项目启动、任务书与交付验收闭环

1. **新项目接入**：AI 按 [项目接入与启动指南](workflows/项目接入与启动指南.md) 读取规范并分阶段提问，项目仓库按 [项目接入指南](projects/项目接入指南.md) 落地专属规则。
2. **正式任务书使用**：由 Gemini 使用 [正式任务书模板](templates/正式任务书模板.md) 起草任务书，经 GPT 审核与用户确认后固化为唯一有效任务入口，历史任务书只增不覆。
3. **实施与单一 ZIP 交付**：Gemini 完成后，将所有新增/修改成品与 `DELIVERY_REPORT.md` 打包为**单一 `.zip` 压缩包**交付用户；软件项目可由 Antigravity 协助校验并提交独立交付分支，创作项目由用户检查后手动提交至 `inbox/gemini/待交付/`。
4. **独立验收与推进**：GPT 对照真实文件、Diff 与测试/自检证据使用 [独立审查报告模板](templates/独立审查报告模板.md) 出具验收结论；用户确认后决定归档、合并或开启下一轮。
